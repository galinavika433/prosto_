# Основные этапы проектирования бд

1. анализ требований
- определить предметную область
- бизнес правила
результат - это четко сформулированное техническое задание

2. концептуальное проектирование
на этом этапе создается модель предметной области, которая отражает ее суть без привязки конкретной **субд** 
задачи данного этапа:
- выделить сущности
- определить атрибуты
- выявить связи между сущностями
- сформулировать ограничение целостности
(возраст, ценник (нельзя вводить отрицательные числа))
результат данного этапа - **ER диаграмма** 

![[Pasted image 20260917143811.png]]


3. логическое проектирование
концептуальная модель преобразовывается в форму, понятную конкретной субд
задачи:
- перевод сущностей в таблицы
- атрибуты в заголовке столбцов
- связи во внутренние и внешние ключи

подбираются типы данных и обязательное или необязательное поле
проводится **нормализация (это процесс устранения избыточности и дублирование данных что бы повысить целостность и эффективность хранения)** 
есть 4 формы нормализации:
- 1NF
- 2NF
- 3NF
- BCNF
результат данного этапа - диаграмма с таблицами, типами данных и ключами

![[Pasted image 20260917145306.png]]


4. физическое проектирование
это самый технический этап, на котором логическая модель адаптируется под конкретную субд
задачи:
- выбор субд (с учетом требований проекта)
- проектирование сущностей, атрибутов, первичных и внешних ключей
- ввод тестовых данных
- проектирование физических ограничений
- реализация бизнес правил (процедуры, триггеры, запросы)
- настройка безопасности (определение прав доступа у пользователей)
результат - готовая база данных, конкретные субд в которые можно вносить реальные данные и использовать
